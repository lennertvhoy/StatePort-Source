# Failure Scan — SP-001a

## Scope

Local template/instance validation and admin CLI.

## Failure modes addressed

### Missing contract file

- **What:** `templates/<name>/.statedd/contract.md` is missing.
- **Effect:** `validate-template` reports `contract.md: required file is missing` and exits non-zero.
- **Prevention:** `check_required_files` enumerates missing required files before parsing.

### Malformed `template.yaml` / `instance.yaml`

- **What:** YAML parse error or non-UTF-8 file.
- **Effect:** Validator reports `YAML parse error: ...` or `file is not valid UTF-8: ...`; CLI exits non-zero.
- **Prevention:** `check_yaml_parseable` catches `StateDDYamlError` and `UnicodeDecodeError` and converts them to `ValidationIssue`s.

### Missing required state files in an instance

- **What:** An instance references a template whose `spec.schemas` list includes files not present under `instance/state/`.
- **Effect:** `validate-instance` reports `state/<file>: required state file missing: ...` and exits non-zero.
- **Prevention:** After resolving and validating the referenced template, `validate_instance` checks each schema path under `instance/state/`.

### Broken `templateRef`

- **What:** `instance.yaml` references a template path that does not exist, is absolute, or is not a directory.
- **Effect:** Validator reports `spec.templateRef.path: template path does not resolve: ...` or `absolute template paths are not allowed`.
- **Prevention:** `check_template_ref_resolves` validates the resolved path and rejects absolute paths.

### Adjacent failures for SP-001b (runner)

- **What:** The runner consumes validated templates/instances and may assume certain fields exist.
- **Risk:** If the runner does not re-validate or guard against malformed data, a template that passes the static validator but has semantic issues (e.g., empty `allowedActions`) could cause runtime errors.
- **Mitigation:** Runner should either reuse `template-validator` before executing or defensively read fields with defaults.
